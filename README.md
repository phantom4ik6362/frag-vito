# Автоответчик Авито

FastAPI принимает сообщения Авито, сохраняет их в SQLite и запускает два фоновых обработчика. Первый выбирает шаблон и отвечает в Авито. Второй отправляет уведомления в Telegram.

## Переезд со старой версии

1. Распакуйте архив в новую папку и скопируйте в неё старый `.env` рядом с `app.py`.
2. Если в `.env` задан `DB_PATH`, проверьте путь и права на запись. Без этой переменной используется `data/queue.sqlite3` в новой папке. Для переноса существующей базы остановите старый сервис и скопируйте согласованную резервную копию SQLite. Схема обновляется при запуске. Для теста на отдельном аккаунте используйте отдельную базу.
3. Для первого запуска установите `DRY_RUN=true`. Остановите старый сервис перед переключением. Запускайте одну копию с одним Uvicorn worker на эту базу.
4. Добавьте параметры Telegram, если нужны уведомления.

Прежние переменные `AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET`, `AVITO_USER_ID`, `WEBHOOK_SECRET`, `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, `REPLY_DELAY_SECONDS`, `DRY_RUN`, `DB_PATH` и `LOG_LEVEL` работают как раньше. URL вебхука остаётся `/webhook/<WEBHOOK_SECRET>`. При смене публичного адреса зарегистрируйте новый URL. При переходе остановите старую подписку, если на аккаунте остался активный старый URL.

## Запуск на Linux или macOS

Из распакованной папки, Python 3.10+.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py check
uvicorn app:app --host 127.0.0.1 --port 8000 --no-access-log --workers 1
```

В другом терминале с активной виртуальной средой проверьте `curl -fsS http://127.0.0.1:8000/health`. Для теста поднимите HTTPS-туннель на порт 8000. На VPS используйте HTTPS reverse proxy и постоянно работающий процесс, например systemd или Docker с постоянным томом SQLite. Исключите URL вебхука из журналов доступа reverse proxy, поскольку его путь содержит секрет.

Если публичный адрес новый, выполните:

```bash
python manage.py subscribe https://bot.example.com
```

Отправьте сообщение с тестового аккаунта. Проверьте `python manage.py jobs`. После проверки установите `DRY_RUN=false` и перезапустите сервис. Для проверки боевого режима отправьте **новое** сообщение. Для Docker можно использовать входящий в архив Dockerfile и постоянный том на `/app/data`.

## Telegram

Добавьте в существующий `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

Создайте бота через @BotFather и укажите его токен. Для личного чата сначала откройте бота и отправьте ему `/start`. Для группы добавьте бота и разрешите ему отправлять сообщения. Укажите числовой ID чата, для группы он обычно отрицательный. Если обе переменные пусты, уведомления выключены.

Каждое новое входящее событие покупателя, включая повторный текст, отправляется в целевой чат один раз при нормальной работе. Повтор доставки **того же события** дедуплицируется по ID сообщения. Уведомление содержит ID диалога и текст покупателя, а для вложения — его тип. Длинный текст сокращается. Уведомления отправляются независимо от выбора автоответа. Telegram-процесс или Telegram webhook не требуются. При `DRY_RUN=true` исходящие отправки в Авито и Telegram отключены.

Посмотреть статусы можно командой `python manage.py telegram-jobs`. Telegram 429 и ошибки подключения повторяются до пяти попыток. При неясном результате отправки запись помечается `unknown`, чтобы автоматический повтор не продублировал сообщение. В Telegram передаются сообщения покупателей, поэтому задавайте чат с доступом только у тех, кто работает с обращениями.

## Поведение автоответчика

- Задержка `REPLY_DELAY_SECONDS` считается от последнего сообщения в серии. Если покупатель отправил приветствие и сразу написал вопрос, бот рассматривает их вместе.
- На первое приветствие или неясное обращение бот уточняет интерес. Повторное приветствие пропускается. На поздний понятный запрос бот может ответить.
- По доставке бот спрашивает населённый пункт, если он неизвестен. Пока ждёт город, другие вопросы оставляет менеджеру. После города отправляет подтверждение и уточняет канал, если покупатель ещё его не выбрал.
- «Расчёт» уточняет статус локации и канал связи, «Улица» сохраняет цену павильона 230 000 ₽ и уточняет город установки и канал. Уже сообщённые данные повторно не спрашиваются. Короткие ответы покупателя с такими данными видны менеджеру в уведомлениях.
- Подтверждение актуальности спрашивает о комплектации. Прямые вопросы о комплектации и ответы о желаемой комплектации в этой ветке переводят чат на ручное ведение. Явная бессмыслица после уточнения интереса также останавливает автоответы.
- Модель получает контекст и выбирает действие. Текст ответа берётся из `messages/`. При ошибке модели автоответ пропускается. Для шаблонов с уточнениями согласованные вопросы удаляются из текста, когда модель распознала соответствующие данные.
- В подтверждении доставки использована фраза «Спасибо, уточним стоимость доставки». Отправка уведомления в Telegram идёт асинхронно, а отдельной заявки на расчёт сервис не создаёт.

## Локальная проверка

```bash
python -m unittest discover -s tests -v
python dry_run_cli.py
```

Тесты используют SQLite во временной папке и локальные заглушки HTTP. CLI вызывает модель из `.env`, сохраняет историю в пределах сеанса и имитирует POST в Авито. Telegram из CLI не вызывается.
